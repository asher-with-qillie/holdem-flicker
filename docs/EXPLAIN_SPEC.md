# 해설 재설계 구현 명세 v3: "줄 하나, 문장 하나"

> 범위: 트레이너 리빌 슬롯, 해설 시트(트레이너·퀴즈·차트 탭·최근 세션 공통), 퀴즈 피드백, 자리별 보기 상세, 그리고 그 화면들에 같이 보이는 문구.
> 근거: 1안("줄 하나, 문장 하나")을 바탕으로 심사 접목 항목을 넣고, 심사가 찾은 결함을 고치고, 카피 감사의 말투 결정과 고쳐 쓰기를 적용했습니다.
> 이 문서의 문장 예시는 모두 실제 차트(`src/poker/data`)로 계산했습니다. 참고 구현과 1,089개 문장 전체는 아래 두 파일에 있습니다. 검증용이고, 구현할 때 그대로 옮겨도 됩니다.
> - `scripts/reference/line-gen.ts (참고 구현, 저장소에 보관)`
> - `tests/__golden__/line-sentences.tsv (기준선)`

## 1. 목적과 원칙

1. **리빌 슬롯**은 5초 안에 세 가지만 보여 줍니다. 이 패의 답(캡슐), 이 패가 속한 차트 줄(13칸 스트립, 이 패에 링), 그 줄을 읽어 주는 해요체 문장 하나입니다. 문장은 패가 아니라 **(상황, 줄)의 속성**입니다. 그래서 같은 줄의 패는 모두 같은 문장과 같은 스트립을 받고, 링만 움직입니다. 학습자는 카드를 넘길 때마다 같은 덩어리를 한 번 더 떠올리게 됩니다.
2. **해설 시트**는 같은 덩어리를 한 번 더 보여 주고(리빌과 글자까지 같은 문장), 두 축을 덧붙입니다. 하나는 줄 축(같은 높은 카드의 반대 수티드 줄 대비)이고, 다른 하나는 자리 축(이 패의 자리별 칩 한 줄과 자리 문장 한 줄)입니다. 그 아래에 숫자 한 줄과 레버 한 문장을 둡니다.
3. 차트가 뒷받침하는 말만 합니다. 줄, 경계, 폭(%), 자리 사실이 그것입니다. 문장이 주장하는 내용(claim)은 전부 테스트가 차트에서 다시 계산해 대조합니다. 사람이 쓴 차트 메모(647개)만 예외이고, '자세히' 안에 둡니다.
4. **지우는 것**은 다음과 같습니다. 결론의 명령형 접두어(`폴드하세요.`)와 이론 이유(91개 템플릿), 왜? 불릿(82개), 예시 2~3줄, 플랍에서는, 플랍 이후 계획 전체(SPR, 체크리스트, 👍/👎, 플레이 계획), 상황, 손패 에세이, 자세한 이유, 레인지 문단, 혼합 빈도 장문입니다. 손패 이론은 자리가 바뀌어도 문장이 같습니다. 그래서 차트에서 가장 어려운 부분, 즉 자리에 따라 경계가 어디로 움직이는지를 하나도 가르치지 못하고, 한 화면에 목소리를 둘로 만듭니다.
5. 학습자가 읽는 모든 문장은 **해요체**로 쓰고, 명령형은 쓰지 않습니다. 동사는 버튼에 적힌 단어만 씁니다. 답은 캡슐이 말하고, 문장은 차트를 서술합니다. 그래서 맞혔든 틀렸든 같은 틀이 나오고, 그 틀이 기억을 떠올리는 단서가 됩니다.

## 2. 어미·말투 규칙

### 2.1 말투 결정 (하나)

**학습자가 읽는 모든 문장은 해요체입니다.** 리빌, 시트, 퀴즈, 차트 셀 시트, 자리별 보기, 용어집 팝오버, 상황 문구, 면책 문구 모두 해당합니다.

- 어미는 `~해요`, `~예요/이에요`, `~돼요`, `~없어요/있어요`, `~섞어요` 가운데서 고릅니다.
- `~거든요`, `~잖아요`, `~죠`, `~답니다`, 느낌표, 이모지는 쓰지 않습니다.
- **명령형 `~하세요`는 학습자용 해설에서 금지합니다.** 코치 탭 steps의 질문형("…아니었나요?")은 코치 규칙(PLAIN_KO_STYLE §5)을 따르고, 이 명세 범위 밖입니다(§8).
- 명사형으로 끝내도 되는 곳은 정해져 있습니다. 숫자 줄(`CO 오픈 29% → 내 콜 37% · 3벳 9%`), 자리 사다리, 칩, 타일 라벨, 캡션(`이 줄 · 오프수트 K`), 시트 제목, 표 캡션, 그리고 자리별 보기 digest(`8곳 전부 폴드 · 그중 1곳은 콜도 섞음`)입니다.

이유는 세 가지입니다. (a) 같은 화면의 UI가 이미 해요체입니다(`정답이에요`, `아쉬워요`, `그대로 두면 자동으로 넘어가요`, `헷갈려요로 표시했어요`). (b) 차트 메모 647개가 해요체입니다. (c) 해요체가 문장마다 한두 글자 짧아서 2줄 클램프에 유리합니다.

### 2.2 어휘 사전 (단서 일관성)

**동사 = 버튼 단어 + 해요/하고.** 캡슐, 선택 버튼, 문장이 같은 단어를 씁니다.

| 액션 | 문장 동사 | 캡슐/버튼 | 받침 | 비고 |
|---|---|---|---|---|
| raise (rfi) | 오픈해요 | 오픈 | 있음 | `열어요`, `올려요`, `오픈 레이즈` 금지 |
| raise (vs_limp) | 레이즈해요 | 레이즈 | 없음 | `림프에 레이즈` 금지 |
| call | 콜해요 | 콜 | 있음 | vs_5bet 버튼도 `콜`(`올인 콜` 폐기) |
| threebet | 3벳해요 | 3벳 | 있음 | |
| fourbet | 4벳해요 | 4벳 | 있음 | cold_4bet 버튼도 `4벳`(`콜드 4벳` 폐기) |
| allin | 올인해요 | 올인 | 있음 | vs_4bet 버튼도 `올인`(`5벳 올인` 폐기) |
| fold | 폴드해요 | 폴드 | 없음 | `접어요` 금지 |
| check | 체크해요 | 체크 | 없음 | |

→ `src/components/ActionBadge.tsx` `actionLabel(…, short=false)`의 다섯 특수 분기는 짧은 이름을 돌려주게 바꿉니다. 360px 선택 버튼 폭은 오히려 줄어듭니다.

**비중어 사전**은 캡슐, 문장, 자리 문장, 자리별 보기가 모두 같이 씁니다. 차트에 실제로 있는 혼합은 7가지뿐입니다(도달 가능한 칸 기준).

| 혼합 모양 (1순위/2순위…) | 칸 수 | 비중어 | 캡슐 | 문장 꼴 |
|---|---|---|---|---|
| 1순위 ≥ 0.999 | — | 없음 | `폴드` | `KQo까지 오픈해요` |
| 계속 75 / 계속 25 | 150 | 주로 | `주로 콜` | `QQ는 주로 콜해요` |
| 계속 75 / 폴드 25 | 91 | 주로 | `주로 콜` | 〃 |
| 폴드 75 / 계속 25 | 82 | 주로 (폴드 쪽) · 가끔 (계속 쪽) | `주로 폴드` | `QJs만 가끔 3벳하고` |
| 계속 50 / 폴드 50 (동점 → 공격적인 쪽이 정답) | 209 | 절반만 | `절반만 오픈` | `KJo는 절반만 오픈해요` |
| 계속 50 / 계속 50 | 83 | 반반 | `3벳·콜 반반` | `QQ는 4벳과 콜을 반반 섞어요` |
| 계속 50 / 계속 25 / 폴드 25 | 13 | 절반만 | `절반만 콜` | `…는 절반만 콜해요` |
| 폴드 50 / 계속 25 / 계속 25 | 3 | 절반은 | `절반은 폴드` | (P0 계열에서만 나옴) |

판정 함수는 하나만 둡니다(`weightWord`, §6). 결과는 `full`(≥0.999), `주로`(1순위 ≥0.6), `반반`(1·2순위 동점이고 2순위가 rest가 아님), `절반만`(그 밖이고 1순위가 계속하는 액션), `절반은`(그 밖이고 1순위가 rest) 다섯 가지입니다. `가끔`은 rest가 1순위인 칸에서 계속하는 쪽 액션을 말할 때만 씁니다. 부분 정답 기준(`grade.ts PARTIAL_THRESHOLD = 0.4`)에 걸리는 칸은 `절반만`과 `반반` 두 경우뿐입니다. 시트의 부분 정답 문장도 이 두 경우에만 나옵니다(§4.2-⑦).

**앱 어휘.** 다른 뜻으로 쓰지 않습니다.

| 말 | 뜻 | 금지 용례 |
|---|---|---|
| 자리 | UTG~BB 좌석만 | `3벳 자리 실수`, `접어야 할 자리` |
| 상황 | 스팟(rfi, vs_open …) | |
| 줄 | 차트의 줄(포켓페어 대각선, 수티드 X 행, 오프수트 X 열, 수티드 커넥터 대각선) | 코치의 `이 줄이 쓴 실수`(→ 성향) |
| 칸 | 차트 셀 | |
| 경계 | 줄에서 계속하는 칸이 끝나는 곳 | `경계 핸드`(→ 경계에 있는 패) |
| 패 | 손패 | `핸드`, `손패` 혼용 금지 |

### 2.3 패턴 규칙 (카피 감사 4개 조각을 합치고 중복을 뺐습니다)

1. **결론은 캡슐이 합니다.** 문장 앞에 판정어(`폴드하세요.`, `올인에는 폴드하세요.`)를 붙이지 않습니다. 이유: 캡슐, 링 버튼, "정답 ✓"과 같은 말을 세 번, 네 번 하게 됩니다.
2. **문장은 차트를 서술합니다.** 주어는 자리이고(`SB는 …`), 손패 이론은 쓰지 않습니다. 손패와 자리를 잇는 인과 절(`앞자리라`, `뒤에 사람이 남아 아무 패나`, `밸류 위주라 받기 어렵습니다`)도 금지합니다.
3. **한 문장에 한 사실.** 두 절까지만 허용하고 쉼표 하나로 잇습니다(`…하고, …해요`). 연결어미를 세 번 잇지 않습니다.
4. **지시어 대신 이름.** `이 패는 거기에 없습니다` 대신 `KTs는 …`, `오프수트 K는 …`처럼 이름을 씁니다.
5. **완곡어 금지.** `~할 만합니다`, `~쪽이 낫습니다`, `~기 어렵습니다`, `노려 볼 만합니다`는 쓰지 않습니다. 차트는 단정합니다. 비중이 섞인 경우는 비중어(§2.2)가 맡습니다.
6. **번역투를 바꿉니다.** `앞서다` → `이기다`, `받아 내다` → `따다`/`밸류`, `값이 싸다` → `콜이 싸다`, `이길 그림` → (삭제), `플랍이 편하다` → (삭제), `버티기 어렵다` → `못 받아요`, `계속 간다` → 액션 이름, `맞추다/깔리다`(자기 페어) → `맞춰도`, `킥커에서 집니다` → `킥커에서 밀려요`, `오픈을 맞으면` → `앞에서 오픈하면`, `3벳을 맞으면` → `3벳을 받으면`.
7. **`의` 소유격을 뺍니다.** `〈자리〉의 3벳은` → `〈자리〉 3벳은`, `상대의 올인 레인지` → `상대 올인 레인지`.
8. **명사를 겹쳐 쌓지 않습니다.** `스퀴즈와 포지션 불리가 겹칩니다` → `스퀴즈당하기 쉽고 포지션도 없어요`. `위주로 대응합니다` → `…아니면 폴드예요`.
9. **숫자는 두 종류만 남깁니다.** 레인지 폭(정수 %, rangeShare)과 섞는 비율(정수 %, 시트에서만)입니다. 예외로 예시 줄 하나에 `셋이 될 확률 12%`를 허용합니다. 승률, 필요 승률, 팟 크기, bb, SPR, 사이즈는 쓰지 않습니다. 소수점도 쓰지 않습니다(`5.1%` 금지).
10. **`가장`은 생성 문장에 쓰지 않습니다**(`제일`). `대부분` → `거의`, `모두` → `전부`, `~에게` → `~한테`(예시 줄).
11. **용어 풀이를 본문에 이어 붙이지 않습니다.** 풀이는 용어집 팝오버(TermScope)만 합니다. 차트 메모 안의 괄호 풀이 `도미네이트(…)`는 사람이 쓴 원문이라 그대로 둡니다.
12. **`당신`과 문장 첫머리의 `나는`을 금지합니다.** 학습자는 `내`/`나`로 부릅니다(`내 오픈 → HJ 3벳`, `SB, 내 차례예요`).
13. **불릿끼리 `다만`/`그래도`로 잇지 않습니다.** 불릿 구조 자체가 시트에서 사라집니다.
14. **한 해설 안에서 같은 서술어를 세 번 쓰지 않습니다.** 줄 문장과 형제 줄 문장이 둘 다 `오픈해요`로 끝나는 것은 허용합니다(같은 축).
15. **조사는 손으로 고르지 않습니다.** 모든 생성기가 `src/poker/ko.ts`(§2.4)를 거칩니다.

### 2.4 조사 규칙

조사는 소리 내어 읽는 마지막 음절로 정합니다. 한 모듈 `src/poker/ko.ts`에 모으고, 지금 흩어져 있는 `seatP`(atlas), `seat`(explain), `handP`, `actP`, `rankP`, `rp`, `hp`를 대체합니다.

| 대상 | 받침 있음 → 이/은/을/과/이에요 | 받침 없음 → 가/는/를/와/예요 |
|---|---|---|
| 자리 | BTN(비티엔) | UTG, HJ, CO, SB, BB |
| 랭크(줄 이름 `수티드 X`, `오프수트 X`) | T(십), 8(팔), 7(칠), 6(육), 3(삼) | A, K, Q, J, 9, 5, 4, 2. **기존 `rankP` 그대로**이고, T는 `텐/티`가 아니라 `십`으로 읽습니다 |
| 패 이름 | 페어 88, 77, 66, 33 | 그 밖의 페어, `…s`(에스), `…o`(오) |
| 액션 | 콜, 3벳, 4벳, 오픈, 올인 | 레이즈, 체크, 폴드 |
| 줄 이름 | (마지막 글자 기준) | 포켓페어, 수티드 커넥터 |
| 숫자 뒤 | `곳`, `명` | `%`(퍼센트), `bb`(비비) |

- 줄 이름 표기는 패 이름과 같은 `T`를 씁니다(`수티드 T을`). `10`은 카드 그림(`10♠`)에만 씁니다.
- 테스트로 고정합니다: 25개 줄 이름 × {을/를, 은/는, 중}, 169개 패 × {은/는, 을/를}, 6개 자리 × 4개 조사, 8개 액션 × {과/와, 을/를, 이에요/예요}.

### 2.5 길이 제한

길이는 가중 폭(em)으로 셉니다. 한글 1, 라틴 문자·숫자 0.6, 공백·문장부호(`·`, `~`, `,`, `.`) 0.3입니다(`emWidth`, §6).

| 문자열 | 한도 | 참고 구현 실측 |
|---|---|---|
| 리빌 줄 문장 | **≤ 42em** (하드), 목표 ≤ 36 | 최대 40.4, 평균 약 27 |
| 캡슐 라벨 | ≤ 8자 | 최장 `절반만 레이즈` 7자 |
| 형제 줄 문장 | ≤ 42em | |
| 자리 문장(시트) | ≤ 46em | |
| 숫자 줄 | ≤ 34em | |
| 레버 문장 | ≤ 30자 | |
| 부분 정답 문장 | ≤ 40자 | |
| 예시 줄(자세히) | ≤ 40자 | |
| 차트 메모 | 제한 없음(사람 작성) | |

### 2.6 금지 표현 (린트 목록, 실제 문구)

학습자용 생성 문자열 전부와, 정리를 마친 차트 메모에 적용합니다.

- **명령형:** `하세요`, `폴드하세요`, `콜하세요`, `오픈하세요`, `올인에는 폴드하세요`, `쓰세요`, `섞으세요`, `마세요`, `정하세요`
- **합니다체·한다체:** 문장 끝 `니다`, `습니다`, `입니다`, `합니다`, `됩니다`, `샌다`, `접는다`, `넓다.`(코치 극값 라벨은 §8)

|---|---|---|---|---|
| 포켓페어 | 모든 페어 | `gridHand(j, j)` | 13칸 전부 | `AA`…`22` |

### 3.3 문장의 재료 (모두 차트에서 계산)

`lineCells(s, line)`는 줄 칸 가운데 **도달 가능한 칸만** 스트립 순서(위 킥커에서 아래로)로 돌려줍니다. 칸마다 담는 값은 `p = primaryAction`(기존 동점 규칙: 공격적인 쪽), `w = p의 비중`, `full = w ≥ 0.999`, `mixList`, `word = weightWord`입니다. `rest = restAction(def)`이고 BB 림프 대응만 `check`, 나머지는 `fold`입니다.

- **run**: 1순위가 같은 칸이 연속된 구간입니다. 계속 run은 `a ≠ rest`인 run입니다. 구간 안에서 `lastFull`은 마지막 full 칸이고, `tail`은 lastFull 뒤에 이어지는 섞인 칸들입니다.
- **단조성**: 칸의 공격성(`AGGRESSION_ORDER`)이 위에서 아래로 줄어들기만 하면 단조롭습니다. **`rowBoundary.monotone`(계속 비중만 봄)은 쓰지 않습니다.** 계속 비중으로는 단조롭지만 1순위가 번갈아 나오는 9개 줄을 이 기준이 잡아냅니다: vs_open BTN:CO, BB:UTG/HJ/CO/BTN/SB의 수티드 A, vs_3bet BTN:SB, BTN:BB, SB:BB의 수티드 A.
- 참고 구현 실측: 줄은 25개입니다(포켓페어 1, 수티드 커넥터 1, 수티드 A~4 11개, 오프수트 A~3 12개). 74개 상황 × 25줄 = 1,850개 가운데 도달 칸이 있는 **1,089개**에 문장이 생기고, 1,089개가 모두 서로 다릅니다. 계속 run 개수 분포는 0개 487, 1개 461, 2개 113, 3개 27, 4개 1입니다. 단조롭지 않은 줄은 33개이고, 그중 31개가 수티드 A 휠 섬, 2개가 BB vs BTN/SB 커넥터 대각선입니다.

| **P4** | 단조롭지 않음 | `〈S〉 〈O〉 〈set〉만 〈V(top)〉하고, 〈C2〉.` | §아래 | 33 |

조각 정의는 다음과 같습니다.

- `〈T〉`(tail 서술, 끝이 `해요`):
  - 한 칸: `〈m〉는 〈w〉 〈V(a)〉해요`
  - 같은 비중어 두 칸: `〈m1〉·〈m2〉는 〈w〉 〈V(a)〉해요`
  - 같은 비중어 세 칸 이상: `〈m1〉부터 〈m2〉까지는 〈w〉 〈V(a)〉해요`
  - 동점(반반): `〈m〉는 〈a1〉과 〈a2〉를 반반 섞어요`
  - 비중어가 다르고 세 칸 이하: 연속된 같은 비중어끼리 묶어 `〈m1〉·〈m2〉는 주로, 〈m3〉는 절반만 〈V(a)〉해요`
  - 그 밖: `〈m1〉부터는 〈a〉를 섞어요`
  - `〈T'〉`는 같은 내용에 끝을 `하고`/`섞고`로 바꾼 것입니다.
- P3: `h1`은 `〈lastFull1〉까지`입니다. run1이 full 한 칸뿐이면 `〈l1〉만`입니다. `h2`는 run2가 줄 끝까지 전부 full이고 rest 칸이 없으면 `〈firstFull2〉부터는 전부`, 그 밖에는 `〈lastFull2〉까지`입니다. rest = check이면 `…하고, 〈f〉부터는 체크해요.`를 덧붙입니다. **run 사이에 낀 섞인 칸은 이름을 대지 않습니다.** 스트립의 분할 색과 그 칸의 캡슐이 전합니다.
- P3h의 `D`: full이 있는 run이 한 칸이면 `〈l〉는 〈V〉`, 여러 칸이면 `〈l〉까지는 〈V〉`이고, full이 없는 run은 `〈T〉` 꼴입니다.
- P4: `top`은 줄에서 가장 공격적인 1순위이고, `set`은 p = top인 칸 전부입니다. 연속 3칸 이상은 `X~Y`, 2칸은 `X·Y`로 묶고, 묶음 사이는 `·`로 잇습니다. 다른 계속 액션 c가 하나일 때 `C2`는 다음과 같습니다.
  - rest 칸이 없으면: `나머지는 전부 〈V(c)〉해요`
  - 줄 처음부터 top과 c만 있는 구간 안에 full-c 칸 l이 있으면: `〈l〉까지 〈V(c)〉해요`
  - 그 밖: `〈c 칸 목록〉는 〈V(c)〉해요`
  - c가 없으면 앞 절만 씁니다(`…만 〈V(top)〉해요.`).

**답은 문장을 바꾸지 않습니다.** 같은 (자리, 줄)이면 답이 오픈이든 폴드든 문장이 글자까지 같습니다. 답과 비중은 캡슐이 전하고, 경계까지의 거리는 오답일 때만 꼬리표가 전합니다.

**폭 폴백**(생성기 안, 결정적): emWidth가 42를 넘으면 (1) `〈O〉 `/`〈Q〉 `를 뺍니다(손패 이름이 줄을 정해 주므로). 그래도 넘으면 (2) 둘째 절을 버리고 첫 절의 `하고`를 `해요`로 바꿉니다. 실측에서는 1건(vs_open SB:BTN 커넥터)만 (1)에 걸리고, (2)는 0건입니다.

- **⑥ 자리 문장**(`seatAxisLine`). 도달 칸만 봅니다.
  - **rfi:** `rfiThesis`의 첫 문장(해요체, §5.4).
  - **S-a**(1순위가 하나): 비중어가 같으면 `〈패〉는 〈ctx〉 어느 자리에서나 〈w〉 〈V〉해요.`(반반이면 `…〈a1〉과 〈a2〉를 반반 섞어요.`). 비중어가 다르면 `〈패〉는 〈ctx〉 〈자리들〉에서 주로, 〈자리들〉에서 항상 〈V〉해요.`
  - **S-b**(1순위가 두 가지이고, 소수 쪽 ≤ 2자리, 다수 쪽 ≥ 2자리): 소수가 full이면 `〈패〉는 〈ctx〉 〈소수〉에서만 〈V(소수)〉해요.` 소수가 섞였고 비중어가 같으면 `〈패〉는 〈ctx〉 〈소수〉에서는 〈w〉 〈V〉하고, 나머지는 〈V(다수)〉해요.`
  - **S-b′**(계속하는 1순위 그룹이 하나이고 ≤ 2자리, 나머지가 전부 폴드나 체크이고 ≥ 2자리): `〈패〉는 〈ctx〉 〈G〉에서 〈w〉 〈V〉하고, 나머지는 〈폴드|체크|폴드나 체크〉예요.`
  - **S-c**(그 밖): `〈패〉는 〈ctx〉 〈자리들〉에서 〈라벨〉, …, 〈자리들〉에서 〈라벨〉예요/이에요.`
  - ctx: vs_open `〈상대〉 오픈에`, vs_3bet `〈상대〉 3벳에`, vs_4bet `〈상대〉 4벳에`, vs_5bet `〈상대〉 올인에`, cold `앞에서 3벳이 나오면`, vs_limp `림프에`.
  - 자리 묶음: 축 순서로 연속 3자리 이상이면 `X~Y`, 그 밖은 `X·Y`.
  - Line { claims }를 함께 만들고, atlas 속성 테스트가 다시 계산합니다.
- **⑦ 자세히**(`more`):
  - `memo`: `chart.notes[hand]` **정리본**(§6.4). 괄호 풀이는 그대로 둡니다.
  - `example`: 메모가 없을 때만, 아래 세 모양 중 하나를 1줄로 씁니다(`oneExample`, 기존 카드 도우미 재사용, 무늬 뒤집기 유지). 해당하지 않으면 null입니다.
    - 중간·작은 페어: `내 2♠2♦ → 플랍에서 셋이 될 확률 12%예요.`
    - `dominatorOf(info)`가 있는 브로드웨이, A, K, Q·J 계열: `내 K♠10♠ vs 상대 A♦K♦ → K를 맞춰도 킥커에서 밀려요.`
    - wheel_ace: `내 A♠5♠ → A를 쥐고 있어 상대 AA·AK 조합이 줄어요.`
  - 둘 다 없으면 ⑦ 줄 자체를 그리지 않습니다.
- 용어집 밑줄(TermScope)은 그대로입니다. 차트 메모 안에서 괄호로 이미 풀이한 용어는 밑줄을 긋지 않는 기존 규칙도 그대로입니다.

### 7.2 새 불변식 (`tests/line.test.ts`, `tests/sheet.test.ts`, `tests/ko.test.ts`)

1. **줄 정의:** 169개 패가 모두 정확히 하나의 줄을 받고, 그 줄의 줄 칸에 자기 자신이 있습니다. 커넥터 줄은 `classifyHand === 'suited_connector'`인 패만 받습니다. slots는 13개이고, 커넥터의 AKs~JTs는 `inLine: false`입니다.
2. **문장 존재:** 74개 상황 × 25줄에서 도달 칸이 있으면 문장이 있고, 없으면 null입니다. 문장 수는 1,089개입니다. 같은 문장이 두 (상황, 줄)에 겹치지 않습니다.
3. **길이:** 모든 줄 문장과 형제 줄 문장이 `emWidth ≤ 42`입니다. 자리 문장 ≤ 46, 레버 ≤ 30자, 숫자 줄 ≤ 34em입니다. 폴백 발생 수 스냅숏은 `noLabel: 1, cut: 0`입니다.
4. **금지 표현:** `BANNED`(§2.6)가 다음 문자열 어디에도 없습니다: 줄 문장, 형제 줄, 자리 문장, 숫자 줄, 레버, 부분 정답 문장, 예시, 캡슐 라벨, atlas Line 전부, `gateText`, `scenarioSituation`, `glossSentence`, `DISCLAIMER`, 정리한 차트 메모 647개.
5. **말투:** 위 문자열의 모든 문장(`.`/`?`로 자름)이 `/(요|요\?)$/`로 끝납니다. 명사형을 허용하는 필드(숫자 줄, 캡슐, 칩, 타일, digest, 제목)는 서술형 어미가 없어야 합니다(`/(니다|해요|예요)$/` 금지).
6. **주장 재계산(속성 테스트):** 1,089개 문장의 `claims`를 차트에서 다시 계산해 전부 참인지 확인합니다(`LineClaim` 7종, §6.1). 문장에 나온 패 이름은 전부 claims에 들어 있어야 합니다(텍스트와 claims 교차 확인: 문장 속 `/[2-9TJQKA]{2}[so]?/`의 집합 = claims 손패 집합 ∪ 줄 정의상 언급 없음).
7. **단서 일관성:** 모든 (상황, 도달 가능 패)에서 `explainStep(step).line.sentence.text === lineSentence(s, lineOf(hand)).text`입니다. 같은 줄의 패끼리 글자가 같고, AtlasDetail에서 쓰는 문자열과도 같습니다.
8. **비단조 회귀:** §3.3의 9개 줄(rowBoundary.monotone은 참이지만 1순위가 번갈아 나옴)과 BB vs BTN/SB 커넥터 줄이 frame `P4`이고, 경계 막대가 null입니다.
9. **캡슐:** §2.2 표의 7가지 혼합 모양마다 라벨을 고정합니다. `capsule.action === step.answer`입니다. partial 문장이 있는 칸 = `actionWeight(step, a2) ≥ PARTIAL_THRESHOLD`인 칸입니다.
10. **near-miss:** 단조 줄에서만 null이 아닙니다. `한 칸 밖`인 패의 p는 rest이고 바로 앞 도달 칸이 마지막 계속 칸입니다. 예: rfi UTG KTo, vs_open SB:UTG KTs.
11. **숫자:** `seatNumbers`의 모든 %가 `Math.round(rangeShare×100)`과 같고, rfi 사다리는 18/21/29/46/46입니다.
12. **레버 데이터 판단:** `SB는 콜을 거의 안 하고…`는 해당 차트 콜 비중이 2% 미만일 때만 나옵니다. 포지션 문장은 `heroIsIP`와 일치합니다. vs_5bet, cold_4bet에는 포지션 문장이 없습니다.
13. **조사 전수표:** §2.4의 모든 조합을 고정합니다(`수티드 T을`, `오프수트 8을`, `수티드 9를`, `88은`, `BTN은`, `콜과`, `레이즈를`, `46%예요`, `6곳이에요`).
14. **반복 금지:** 한 Explanation 안에서 같은 서술어가 세 번 이상 나오지 않습니다(줄 문장과 형제 줄의 `…해요` 두 번은 허용).
15. **레이아웃**(`scripts/layout-audit.mjs` 확장, Playwright): 360×640과 390×844에서 §3.6의 13칸과 emWidth 상위 30개 문장으로 리빌을 렌더합니다. `.trainer-answer__reason`이 2줄 이하이고(scrollHeight ≤ 2×18+1), 슬롯 높이가 120/114에서 변하지 않고, 스트립 폭이 297px이며 가로 스크롤이 없는지 확인합니다. 퀴즈 피드백과 시트도 같은 표본으로 캡처합니다.
