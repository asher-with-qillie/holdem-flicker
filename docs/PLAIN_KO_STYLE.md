# 한국어 해설 스타일 가이드 (v3)

읽는 사람: 포커를 막 시작한 중고등학생. 목표는 **차트 암기: 줄과 경계를 말한다**. 용어 제거가 아니다.
구현 명세는 `docs/EXPLAIN_SPEC.md`. 조사·동사·폭·금지 표현은 전부 `src/poker/ko.ts` 한 곳에 있다.

## 0. 가장 중요한 원칙 — 포커 용어는 그대로 쓴다

폴드·콜·레이즈·킥커 같은 말은 한국 포커판에서 쓰는 표준 용어다.
이걸 "접어요 / 따라 내요 / 옆 카드"처럼 억지로 풀면 **오히려 어색하고, 실제 게임에서 못 알아듣는다.**

- ❌ "이 패는 접는 게 맞아요" → ✅ "폴드해요"
- ❌ "상대 A♦5♦ 같은 뻥" → ✅ "상대의 A5s 블러프"
- ❌ "페어를 맞춰도 옆 카드에서 지기 쉬워요" → ✅ "페어를 맞춰도 킥커에서 밀려요"
- ❌ "같은 숫자 3장(셋)" → ✅ "셋"
- ❌ "다시 올리는(3벳)" → ✅ "3벳"
- ❌ "칩을 다 거는(올인)" → ✅ "올인"

## 1. 용어 3단계

### A. 그대로 쓴다 (설명 없음)
폴드 · 콜 · 레이즈 · 체크 · 벳 · 오픈 · 3벳 · 4벳 · 5벳 · 올인 · 블러프 · 밸류 ·
페어 · 포켓페어 · 오버페어 · 탑페어 · 투페어 · 셋 · 트립스 · 스트레이트 · 플러시 ·
킥커 · 드로우 · 플러시 드로우 · 스트레이트 드로우 · 보드 · 플랍 · 턴 · 리버 ·
포지션 · 블라인드 · 팟 · 스택 · 레인지 · 수티드 · 오프수트 · 커넥터 · 브로드웨이 ·
UTG · HJ · CO · BTN · SB · BB

### B. 풀이는 용어집 팝오버에서만 한다

본문에 풀이를 이어 붙이지 않는다. 풀이 문장(`glossSentence`)은 해요체 한 문장이다: "블로커는 내가 그 카드를 들어 상대 조합이 줄어드는 효과예요."
사람이 쓴 차트 메모 안의 괄호 풀이 `도미네이트(…)`는 원문이라 그대로 둔다.

| 용어 | 붙이는 말 |
|---|---|
| 블로커 | 블로커(내가 그 카드를 들어 상대 조합이 줄어드는 효과) |
| 도미네이트 | 도미네이트(같은 카드를 맞춰도 킥커에서 지는 상태) |
| 셋마이닝 | 셋마이닝(셋을 노리고 콜하는 것) |
| 팟 오즈 | 팟 오즈(콜 금액 대비 팟 크기) |
| 임플라이드 오즈 | 임플라이드 오즈(맞았을 때 더 딸 수 있는 몫) — `받아내다`는 §1.C 번역투라 `따다`로 |
| 스퀴즈 | 스퀴즈(오픈과 콜 뒤에 크게 올리는 것) |
| c-bet | c-bet(프리플랍 레이저가 플랍에서 잇는 벳) |
| SPR | SPR(팟 대비 남은 스택 비율) |
| 세미 블러프 | 세미 블러프(드로우를 들고 하는 블러프) |
| 백도어 | 백도어(두 장을 더 맞아야 완성되는 드로우) |
| 리버스 임플라이드 오즈 | 맞고도 더 큰 패에 지는 위험 |
| 인포지션 / 아웃오브포지션 | 포지션이 있다 / 없다 (또는 "먼저 액션") |

### C. 아예 안 쓴다 → 쉬운 말로 바꾼다
| 쓰지 말 것 | 대신 |
|---|---|
| 에퀴티 | 승률 |
| 폴드 에퀴티 | 상대가 폴드할 가능성 |
| 리니어 / 폴라 / 양극화 | "강한 패 위주" / "강한 패와 블러프만" |
| 콤보 | 조합 |
| GTO·솔버 (해설 본문) | "기준 전략" (필요할 때만) |
| 뻥 | 블러프 |
| 옆 카드 | 킥커 |
| 같은 숫자 3장 | 셋 |
| 미리 낸 돈 | 블라인드 |

**번역투는 이렇게 바꾼다** (`docs/EXPLAIN_SPEC.md` §2.3-6, §2.6. `ko.ts BANNED`가 막는다)

| 쓰지 말 것 | 대신 |
|---|---|
| 앞서다 | 이기다 |
| 받아 내다 | 따다 / 밸류 |
| 값이 싸다 | 콜이 싸다 |
| 이길 그림 · 플랍이 편하다 | (삭제) |
| 버티기 어렵다 | 못 받아요 |
| 계속 간다 | 액션 이름(콜해요 · 3벳해요) |
| 깔리다(자기 페어) | 맞춰도 |
| 킥커에서 집니다 | 킥커에서 밀려요 |
| 오픈을 맞으면 · 3벳을 맞으면 | 앞에서 오픈하면 · 3벳을 받으면 |
| 열어요 · 접어요 | 오픈해요 · 폴드해요 |
| 오픈 레이즈 · 5벳 올인 · 올인 콜 · 콜드 4벳(버튼) | 오픈 · 올인 · 콜 · 4벳 |
| 혼합 빈도 · 경계 핸드 · 근사치 | 섞는 비율 · 경계에 있는 패 · (삭제) |
| 전체의 약 N% | N% |
| ~할 만합니다 · ~쪽이 낫습니다 · ~기 어렵습니다 | (차트는 단정한다. 비중은 비중어가 맡는다) |
| 위주로 대응 · 포지션 불리 | …아니면 폴드예요 · 포지션이 없어요 |

### D. 앱 어휘 (다른 뜻으로 쓰지 않는다)

| 말 | 뜻 | 금지 용례 |
|---|---|---|
| 자리 | UTG~BB 좌석만 | `3벳 자리 실수`, `접어야 할 자리` |
| 상황 | 스팟(rfi, vs_open …) | |
| 줄 | 차트의 줄(포켓페어 대각선, 수티드 X 행, 오프수트 X 열, 수티드 커넥터 대각선) | 코치의 `이 줄이 쓴 실수`(→ 성향) |
| 칸 | 차트 셀 | |
| 경계 | 줄에서 계속하는 칸이 끝나는 곳 | `경계 핸드`(→ 경계에 있는 패) |
| 패 | 손패 | `핸드`, `손패` 혼용 금지 |
## 2. 읽기 쉬운 문장 규칙

1. **한 문장 = 한 가지 정보.** 길이는 가중 폭(em: 한글 1 · 라틴/숫자 0.6 · 공백/문장부호 0.3, `ko.emWidth`)으로 잰다.

   | 문자열 | 한도 |
   |---|---|
   | 리빌 줄 문장 | ≤ 42em (하드), 목표 ≤ 36 |
   | 캡슐 라벨 | ≤ 8자 |
   | 형제 줄 문장 | ≤ 42em |
   | 자리 문장(시트) | ≤ 46em |
   | 숫자 줄 | ≤ 34em |
   | 레버 문장 | ≤ 30자 |
   | 부분 정답 문장 | ≤ 40자 |
   | 예시 줄(자세히) | ≤ 40자 |
   | 차트 메모 | 제한 없음(사람 작성) |
2. **결론은 캡슐이 한다. 문장은 차트를 서술한다(자리 + 줄 + 경계).** 문장 앞에 `폴드하세요.` 같은 판정어를 붙이지 않는다.
3. **괄호는 한 문장에 최대 1개.** 괄호 안에 괄호 금지.
4. **같은 설명 반복 금지.** 한 해설 안에서 용어 설명은 딱 한 번.
5. **학습자가 읽는 모든 문장은 해요체. 명령형 금지. 명사형은 숫자 줄, 칩, 캡션만.**
   어미는 `~해요`, `~예요/이에요`, `~돼요`, `~없어요/있어요`, `~섞어요`. `~거든요`, `~잖아요`, `~죠`, `~답니다`, 느낌표, 이모지는 쓰지 않는다.
   패턴 규칙 15개(`docs/EXPLAIN_SPEC.md` §2.3):
   1. 결론은 캡슐이 한다. 문장 앞에 판정어(`폴드하세요.`)를 붙이지 않는다.
   2. 문장은 차트를 서술한다. 주어는 자리(`SB는 …`)이고 손패 이론은 쓰지 않는다. 손패와 자리를 잇는 인과 절도 금지.
   3. 한 문장에 한 사실. 두 절까지, 쉼표 하나로 잇는다(`…하고, …해요`).
   4. 지시어 대신 이름(`KTs는 …`, `오프수트 K는 …`).
   5. 완곡어 금지(`~할 만합니다`, `~쪽이 낫습니다`). 비중은 비중어(주로 · 절반만 · 반반 · 절반은 · 가끔)가 맡는다.
   6. 번역투를 바꾼다(§1.C 표).
   7. `의` 소유격을 뺀다(`BTN 3벳은`).
   8. 명사를 겹쳐 쌓지 않는다(`스퀴즈당하기 쉽고 포지션도 없어요`).
   9. 숫자는 레인지 폭(정수 %)과 섞는 비율(정수 %, 시트에서만) 두 종류. 예외는 예시 줄의 `셋이 될 확률 12%`. 소수점 금지.
   10. 생성 문장에 `가장`을 쓰지 않는다(`제일`). `대부분` → `거의`, `모두` → `전부`, `~에게` → `~한테`.
   11. 용어 풀이를 본문에 이어 붙이지 않는다(§1.B).
   12. `당신`과 문장 첫머리의 `나는`을 금지. 학습자는 `내`/`나`(`SB, 내 차례예요`).
   13. 불릿끼리 `다만`/`그래도`로 잇지 않는다.
   14. 한 해설 안에서 같은 서술어를 세 번 쓰지 않는다(줄 문장과 형제 줄의 같은 끝맺음은 허용).
   15. 조사는 손으로 고르지 않는다. 전부 `ko.josa`를 거친다(BTN은 · 수티드 T을 · 88은 · 46%예요).
6. **숫자는 퍼센트로.** 리빌에는 %를 쓰지 않는다. 시트의 %는 `rangeShare`를 반올림한 정수 하나의 기준이다(0보다 크고 0.5 미만이면 `1% 미만`).
7. **불릿은 명사·동사로 시작.** "AK는 …", "뒤에 5명이 남아서 …".

### 좋은 예 / 나쁜 예
- ❌ "폴드하세요. K 하나뿐이고 오프수트라 만들 수 있는 패가 없습니다." (판정어 · 손패 이론 · 합니다체)
- ✅ "UTG는 오프수트 K를 KQo만 오픈하고, KJo는 절반만 오픈해요."
- ✅ "BB는 CO 오픈에 포켓페어를 TT까지 3벳하고, 88부터는 전부 콜해요."
- ✅ "SB는 UTG 오픈에 수티드 Q를 QJs만 가끔 3벳하고, 나머지는 폴드해요."

## 3. 예시 쓰는 법

예시는 '자세히' 안에 **1줄**, 차트 메모가 없을 때만 쓴다. 모양은 세 가지뿐이다(`sheet.oneExample`).

```
내 2♠2♦ → 플랍에서 셋이 될 확률 12%예요.
내 K♠10♠ vs 상대 A♦K♦ → K를 맞춰도 킥커에서 밀려요.
내 A♠5♠ → A를 쥐고 있어 상대 AA·AK 조합이 줄어요.
```

- 카드는 ♠와 ♦만 쓴다. 같은 카드가 두 번 나오지 않게 한다. 40자 이내.
- 어미는 `밀려요`, `줄어요`, `12%예요`. 승률 숫자는 쓰지 않는다.

## 4. 해설 구조 (앱 화면 순서, `docs/EXPLAIN_SPEC.md` §3 · §4)

**리빌 슬롯**(5초 안에 세 가지):
1. **캡슐** — 답 × 비중어(`폴드`, `주로 콜`, `절반만 오픈`, `4벳·콜 반반`). 오답·부분 정답이면 `한 칸 밖`/`마지막 칸` 꼬리표.
2. **LineStrip** — 이 패가 속한 차트 줄 13칸, 이 패에 링, 경계 막대.
3. **줄 문장** — (상황, 줄)의 속성인 해요체 한 문장. 같은 줄의 패는 전부 같은 문장을 받는다. 이 밖에는 아무것도 두지 않는다.

**해설 시트**:
1. 줄 블록 — 캡슐, `이 줄 · 오프수트 K`, 스트립, 리빌과 글자까지 같은 줄 문장.
2. 형제 줄 — 같은 높은 카드의 반대 수티드 줄(`수티드 K는 K9s까지 오픈해요.`).
3. 섞인 칸 — 섞는 비율 칩, 부분 정답 문장(2순위 ≥ 40%일 때만).
4. 자리 — 숫자 줄(`CO 오픈 29% → 내 콜 37% · 3벳 9%`, rfi 는 사다리).
5. 레버 — 자리 사실 한 문장(`BB는 이미 1bb를 냈으니 1.5bb만 더 내면 돼요.`).
6. 이 패, 다른 자리에서는 — 자리 칩 한 줄과 자리 문장 한 줄.
7. 자세히(접힘) — 차트 메모, 메모가 없을 때만 예시 1줄. 둘 다 없으면 줄째로 숨긴다.
8. 림프 대응이면 면책 문구.

## 5. 코치 탭 전용 규칙

코치 탭은 차트를 다시 읽어 주는 곳이 아니다. 차트가 할 말("이 패는 이 자리에서 폴드입니다")은
차트 탭이 이미 한다. 코치는 **어떻게 생각하면 되는지**와 **다음 판에 뭘 바꾸면 되는지**를 말한다.

### 카드 3단 계약

한 장 = 제목 → 내 기록 → 생각 절차. `src/state/coach/lint.ts` 가 이 계약을 코드로 강제하고,
규칙이 만든 카드든 AI가 만든 카드든 **같은 린터**를 통과해야 화면에 올라간다.

| 칸 | 무엇 | 길이 |
|---|---|---|
| `title` | 무엇이 새는지. 단정문. | 20자 |
| `evidence` | 내 기록 한 줄. 반드시 내 통계여야 한다. | 30자 |
| `steps` | 생각 절차 2~3줄. **마지막 줄은 질문**으로 끝낸다. | 각 25자 |

마지막 줄을 질문으로 끝내는 것이 핵심 장치다. 질문은 다음 판에 스스로 던질 수 있는 것이어야 한다.

- ✅ "이 패를 UTG라고 생각하고 접은 건 아닌가요?"
- ❌ "BTN에서는 더 넓게 오픈하세요." (지시로 끝나면 차트 요약이 된다)

### 코치 탭에서 추가로 금지하는 것

| 쓰지 말 것 | 왜 |
|---|---|
| 핸드 단위 단정 ("AJo는 UTG에서 폴드입니다") | 앱 차트와 어긋난다. `rfi.ts` 의 UTG 레인지에는 `AJo+` 가 들어 있다. 기준은 늘 **클래스 단위**(오프수트 A, 수티드 커넥터)로 말한다 |
| 레인지 표기 (`ATo+`, `KJs+`) | 차트 문법이다. 코치는 차트를 읽어 주지 않는다 |
| 레인지 퍼센트 ("상위 18%"), 혼합 빈도 ("30/70") | 같은 이유 |
| GTO · 솔버 · EV · MDF · 노드 · 밸런스 | 3의 C단계보다 더 좁게 막는다 |
| "스택이 깊으면 / 얕으면" | 이 앱은 100bb 고정이다. 없는 변수를 말하지 않는다 |
| 한 카드에 손패 이름 3개 이상 | 나열이 시작되면 차트가 된다 |
| 사람에 대한 평가 ("당신은 도박사예요") | 행동만 말한다. "문제를 풀 때 이렇게 기웁니다" |
| 느낌표 · 이모지 | 앱 전체의 말투 |

퍼센트는 두 곳만 허용한다. (1) `evidence` 안의 내 정답률·횟수, (2) 3절이 명시한 확률(셋 12% 등).

코치 문구의 합니다체 정리는 별도 작업이다(`docs/EXPLAIN_SPEC.md` §8).
